INTEGRATION — CHARACTERS TRACK (Dungeon of the Covenant)
====================================================
Date: 2026-09-25 | Track: 2a CHARACTERS | Author: characters build subagent

WHAT WAS BUILT
--------------
Three new modules (client/js/) + wiring inside client/js/entities.js.
All existing exported names/signatures kept (EntityManager, syncPlayers,
syncMobs, syncBoss, triggerAttackAnimation, update, attachEntityGLB, ...).

  characterMaterials.js  - PBR upgrade pass: procedural micro-detail + cloth-weave
                           normal maps, per-kind tuning (metal/cloth/bone/glow),
                           shared PMREM RoomEnvironment reflections applied to
                           CHARACTER materials only (dungeon untouched).
  characterAnimation.js  - Procedural combat layer: hit flash (hp-drop driven),
                           attack lunge (root forward push), boss death
                           tip-over + sink + fade, with reset.
  characterLighting.js   - Rim/back light rig (one DirectionalLight on layer 1,
                           repositioned opposite the camera every frame) +
                           blob contact shadows (radial-gradient planes that
                           stay flat when a hero tips over).

COORDINATOR: ADD TO client/js/main.js
--------------------------------------
1. Import (top of file, next to the other imports):

   import { initCharacterRimLight } from './characterLighting.js?v=9.0';

2. Init calls — place immediately AFTER the EntityManager is constructed
   (currently: `this.entities = new EntityManager(this.renderer.scene);`):

   // characters track: rim light rig + PBR environment for characters
   initCharacterRimLight(this.renderer.scene, this.renderer.camera);
   this.renderer.camera.layers.enable(1);      // rim light lives on layer 1 only
   this.entities.setRenderer(this.renderer.renderer); // char PBR env reflections

   Notes:
   - No per-frame main.js call is needed: EntityManager.update(dt) already
     drives updateCharacterLighting() + updateCombatAnimation() internally.
   - setRenderer() is safe to call once; groups built later pick up the env
     map automatically, earlier groups are upgraded retroactively.
   - The rim light affects ONLY character meshes (layer 1); the dungeon keeps
     its existing lighting. Overhead-bar sprites are unaffected (unlit).

BOSS CHANGE (entities.js createBossMesh)
----------------------------------------
Removed the `attachEntityGLB(bodyGroup, '/assets/models/boss_sovereign.glb', ...)`
mount. Rationale (bbox-verified): the GLB is origin-centered (y -1.58..1.43) and
2.9 units wide — at any grounded offset it either sat half-buried or clipped
through the larger sculpted procedural colossus built over it (x half-width 1.81
> torso radius ~1.35). It contributed only clipping clutter + wasted draw calls.
The procedural molten colossus IS the boss. models/ directory untouched.
Boss death now plays tip-over + sink + fade (was: instant hide).
